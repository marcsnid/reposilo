Retention

How much history to keep per repo. -1 keeps everything, 1 keeps only the newest. Per-repo overrides live on each repo page.

Release binaries

Also download the binary assets attached to releases (not just the source snapshot), for the platforms you select. Assets are classified from their filenames, so foo-win64.zip, foo-x86_64-unknown-linux-gnu.tar.gz and foo_1.2_amd64.deb all match. Source tarballs and assets that don’t name an OS and architecture are skipped. Leave everything unchecked to disable.

{% for p in ctx.release_platforms %} {% endfor %}

Each filter is a full slug (linux-x64), an OS (linux), an arch (arm64) or all; comma or space separated.

Scheduler

How often the background loop checks remotes. Unchanged repos cost a single ls-remote; nothing is cloned unless something moved.

A remote unreachable for this many consecutive days is marked dead and the scheduler stops contacting it. 0 = never declare dead. A manual refresh resurrects it if it ever comes back.

llama.cpp

Any OpenAI-compatible endpoint (llama-server, ollama, LM Studio, a LAN box). Used for two things: auto-tagging (batch tags repos from their READMEs) and the llama.cpp button on the import review form, which reads a mystery zip’s fingerprint (filename, file list, README excerpt) and proposes a project name plus GitHub search queries to track down zips the offline detection couldn’t identify.

OpenTelemetry

Optional: push metrics (repos, refreshes, failures, releases) to an OTLP/HTTP collector. The built-in Stats page always works without this.

Instance

Fixed for the running server: edit the config file and restart to change these.

AI tagging

Runs the configured llama.cpp over all untagged repos (batched, README-based). Configure the endpoint above first.

Import a zip collection

Point reposilo at a folder of zipped repositories; detection, GitHub suggestions and llama.cpp identification take it from there.
